# HeDa - Domain Model

---

## About the Project
HeDa (Healthy Debate App) is a digital platform that promotes respectful, public discussions on various topics.  
Users can join or start debates, moderators can review reports, and donations help sustain the platform.

---

HeDa is a digital platform for hosting and participating in public debates where:

- **Users** can create and join open discussions (debates) on various social or ethical topics.  
- **Debates** allow structured arguments, public visibility, and AI-assisted moderation.  
- **Reports** can be submitted by users or automatically generated by the AI moderation system.  
- **Moderators** review reports, remove inappropriate content, and maintain healthy discussions.  
- **Donators** support the platform through financial contributions to sustain server and moderation costs.  
- **Data Analysts** monitor activity trends and moderation efficiency through an analytics dashboard.  
- **AI Moderation** detects suspicious or harmful behavior patterns (spam, harassment, misinformation).  
- **Payments** and donation processing are handled via external APIs with verified transaction results.

---


## Entities
Have unique identities and lifecycles.

| Entity | Why it's an Entity |
|---------|--------------------|
| **User** | Has unique ID, lifecycle (Interacting → banned → unbanned), state changes as users interact. |
| **Moderator** | Has unique identifier, lifecycle (currently working → paid → on break). |
| **Donator** | He is identifiable using his payment information, and is also related to donation ID. |
| **Debate** | Has unique ID, can have many states like ‘ongoing’ / ‘empty’ (when no one but you is part of it). |
| **Report** | Has unique ID, tracking who reported who and for what reasons. |
| **Donation** | Has unique transaction ID, tracks payment lifecycle. |
| **Data Report** | Has unique ID, can be currently fetching data or 'sent to data analyst'. |

---

## Value Objects
Immutable, compared by value.

| Value Object | Description |
|---------------|-------------|
| **Report Category** | Reason or classification for a report (e.g., Spam, Harassment). |
| **Conversation Data** | Log and metadata of debate discussions. |
| **Payment Result** | Outcome of a donation transaction (Success, Failed, Pending). |
| **Suspicious Activity** | Pattern detected by AI moderation system. |
| **Donation Amount** | Monetary value of a donation. |

---


## Invariants
Business rules that must always hold true.

- Minimum characters - Cannot respond or create a debate with blank text
- Minimum Payment - Cannot do a null payment
- Categorize report - User cannot report without specifying the category
- Review report - Report must be reviewed by a moderator before a sanction
- Mandatory login - User cannot report or post without being connected
- Payment feedback - Donation must lead to a payment result
